# AU patch set over the pinned SI assertion corpus

Each `.sql` under `scripts/` is an AU-edited copy of the SNOMED International
script at the same corpus-relative path, at the pin `ASSERTIONS_REF`
(`0160dd2e`) in `../checkout-resources.sh`. That script clones the pin and then
copies every file here over the clone, printing each one; it fails if a target
does not exist in the clone, so a pin bump that renames a script fails instead
of leaving a stray file no manifest names. UUIDs, file names and manifest
entries are unchanged: RVF runs the AU text under the SI identity.

The bundled DuckDB store (`../src/main/resources/duck/store.json`) is published
from the overlaid corpus, pack `international 2026.10.07`
(`sha256:81002053cc1adf4f`); see `../duck/README.md` for why the version is
explicit. Changing a file here means republishing it.

Rulings are those of AU nightly triage run 1789600580440 (`R1`, `R3`, `R4`, `R7`,
`R9`). Counts are from executing the published store, before (`2026.07.27`) and
after (`2026.09.30`; `6614ff12` re-measured at `2026.10.07`), over the Parquet materialisation of
`SnomedCT_ManagedServiceAU_DAILYBUILD_BETA_AU1000036_20260930T120000Z`, bound
the way `DuckBinder` binds them for the nightly's configuration:
`includedModules=32506021000036107,351000168100`,
`defaultModuleId=32506021000036107`, `effectiveTime=20260930`, no dependency
release. Where the old nightly configuration (no `includedModules`, no
`defaultModuleId`) gives a different before count, both are shown.

## `component-centric-snapshot-language-valid-moduleid.sql`

- **uuid** `17b6c41e-9bf2-456f-ba59-9ad8230d7e52`
- **ruling** R1/R9: a member may sit in a different module from its description
  when an active MDRS row links the two modules in either direction. One rule,
  config-independent.
- **before** two branches on `<INCLUDED_MODULES>`:
  `('NULL' <> '<INCLUDED_MODULES>' and c.id is null and a.moduleid <> '900000000000207008' and a.moduleid not in (<INCLUDED_MODULES>))`
  `or ('NULL' = '<INCLUDED_MODULES>' and a.moduleid <> b.moduleid and not (b.moduleid = '900000000000012004' and a.moduleid = '900000000000207008'))`,
  with `c` a LEFT JOIN on the dependency release's langrefset.
- **after** `a.moduleid <> b.moduleid and not (b.moduleid = '900000000000012004' and a.moduleid = '900000000000207008') and not exists (active MDRS row with (moduleid, referencedcomponentid) = (a.moduleid, b.moduleid) or (b.moduleid, a.moduleid))`.
  No `<INCLUDED_MODULES>` and no dependency join remain, so configuration cannot
  change the answer. The model-module tolerance is kept but is redundant on this
  release (the international MDRS row `900000000000207008 -> 900000000000012004`
  covers the same 7,378 members); it matters only for a package that does not
  carry that row.
- **measured** 1,406,813 (old config) / 1,591 (new config) -> 0 under both.
  Of 1,414,191 active members whose module differs from their description's,
  0 lack an MDRS link.

## `file-centric-snapshot-correct-module-id.sql`

- **uuid** `0145fbad-f067-41ff-b700-cf54fc639e21`
- **ruling** the missing active filter, minimal variant: the
  `moduledependencyrefset` statement only.
- **before** per `*_s` table, generated by `validate_module_id`:
  `select id, moduleid from <table> where moduleid not in (select moduleid from module_id)`.
- **after** the same, then one statement removing exactly what the
  `moduledependencyrefset` statement reported for INACTIVE rows:
  `delete from qa_result where run_id = <RUNID> and assertion_id = '<ASSERTIONUUID>' and details in (select concat('moduledependencyrefset', ' ::id= ', id, ' ::module id: ', moduleid, ' is not in module dependency list') from curr_moduledependencyrefset_s where active = '0')`.
  The statement to filter is generated inside the stored procedure (one per
  table), so there is no `WHERE` in this file to add `active = 1` to; the
  procedure is shared resource SQL and every other table keeps its behaviour.
  The effect equals `active = 1` on that one statement. Note that with the
  filter the `moduledependencyrefset` statement can no longer fire at all: an
  active MDRS row's module is in `module_id` by construction. The other 28
  tables are still checked, active or not, as before.
- **measured** 10 -> 0.

## `component-centric-snapshot-description-valid-characters.sql`

- **uuid** `6614ff12-fca2-42b7-a5da-ea26353979fe`
- **ruling** R3: the rule does not apply to AMT. The FSN statement exempts
  descendants-or-self of `373873005`, `774167006`, `260787004`.
- **before** (FSN statement) `... and term REGEXP '[\\\t\r\n\Z\@$#]' and <latest delta row>`
- **after** the same, plus `and a.conceptid not in (<the three roots>) and a.conceptid not in (<recursive CTE: inferred IS A ancestors of every concept with a flagged FSN, kept where the ancestor is one of the three roots>)`.
  Not the `isKindOf_cr` macros amtv4 uses: those come from the AMT
  pre-requisites, and on the MySQL engine an international-only run has no
  such function, so the assertion failed to execute (`-1` findings, image build
  16924). The CTE runs on both engines. The synonym statement is unchanged.
- **measured** 0 -> 0 on this build (the check reads the delta, which has no
  such FSN). With every active snapshot FSN injected as a delta row: 4 -> 0 (the
  `Lot420 Gelato #33` family, same shape as the validated build's 4 `Terphogz
  Gelanoidz #20` findings).
- **known defect, not fixed here:** backslash is not in the character class.
  `'[\\\t...'` is the MySQL string `[\<TAB>...` - the publisher renders exactly
  that - and the regex engine reads `\<TAB>` as an escaped tab. Measured on
  DuckDB (RE2); ICU, MySQL 8's engine, also treats `\` as quoting the next
  character (not measured here, no MySQL available). Only a POSIX bracket
  expression (MySQL 5.7's Henry Spencer engine) takes `\` literally. The source
  needs `'[\\\\\t...'`.
